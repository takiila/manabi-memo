# 同じアカウントで複数端末を使う

デスクトップPC、ノートPC、スマートフォンで同じアカウントにログインし、各端末でクラウド同期を開始します。初回は端末とクラウドの内容を確認してから同期を有効にします。

ノート、講義、時間割、付箋、PDFの参照情報、課題の締切と完了状態、試験、Campusの個人データを同期します。PDF本体が端末にない場合も、ほかの学習データを編集・同期できます。

PDF本体の保存先はPDFごとに選べます。

- 「追加した端末だけ」: PDF本体は送信しません。別端末でPDFを開く場合は、同じファイルを追加します。内容の一致をSHA-256で確認します。
- 「全端末に同期」: PDF本体も同期します。従来のPDFはこの設定を引き継ぎます。新しく追加するPDFは端末だけの保存が初期設定です。

同期を開始した端末では、画面の表示中に15秒ごとに更新を確認します。画面へ戻ったときや接続が復帰したときにも確認します。オフラインの編集は先に端末へ保存し、接続後に同期します。端末とクラウドの両方が変更されている場合は、確認画面で残す内容を選びます。自動で競合を統合する機能はありません。

同期の開始、重複防止、終了、中断は専用のcontrollerで管理します。受信中の編集、同期停止、アカウント変更を検知し、保存が確定する前ならIndexedDBの保存全体を取り消します。これはGUI設計の記事の、表示と処理の制御を分ける考え方を同期部分へ適用したものです。

別端末でPDFを変更・削除しても、手元のPDF本体は端末内へ保管します。内容が一致しないPDFを新しいPDFとして表示しません。「この端末に残した旧PDFを確認」から保管したファイルを保存できます。通常の学習データのバックアップには旧PDFの保管分を含めないため、必要な旧PDFは個別に保存してください。

## 検証

`npm run test:all` は型、lint、モデル、ビルド、同期APIを検証します。`npm run test:sync-browser` は独立した3つのブラウザー環境で、端末間の送受信、PDFのない端末、締切と完了状態、オフライン復帰、編集競合、保存中断、スマートフォン幅の表示を確認します。Windowsではインストール済みのMicrosoft Edgeを使います。ほかの環境ではPlaywrightのChromiumが必要です。

ブラウザーテストはローカルの認証用fixture、SQLite、一時ファイルストアを使います。実際のFirebase、公開環境のPostgreSQLとPDFストレージ、実機3端末での受け入れ確認は別途必要です。
