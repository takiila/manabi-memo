# まなびメモ：合意済みプロダクト方針・開発継続メモ（2026-10-10）

この文書は、利用者と相談して決定した方針を別セッションの開発担当へ継承するためのもの。PR #8 や既存の `AGENTS.md` / `docs/development/planner-design.md` と併読する。「設計上の合意」と「実装済み・検証済み」は別物とし、できていない機能を完成扱いしない。

## 絶対条件

- **追加費用0円**。従量課金のAI APIや有料DB／ホスティングに依存させない。無料枠の制約や運用条件を確認してからサービスを採用。
- **offline-firstかつ非破壊**。既存授業・ノート・PDF・付箋・タグ・ごみ箱・保存形式・バックアップ・クラウド同期の動作を維持。削除や置き換えより履歴・復元・衝突検出を優先。
- **同一利用者のPC・ノートPC・スマホで授業、授業回、ノート本文、付箋、タグ、課題、ToDo、カレンダー情報を同期**。PDF本体は端末ローカルでもよいが、所在・参照ページ・紐付けなどのメタデータは共有する。別アカウントへの自動アップロード・復元は禁止。
- 一般公開の `main` へのマージ・本番デプロイ・既存ChatGPT Site更新は、**利用者が最終確認・承認するまで禁止**。作業対象は原則既存PR #8（`feat/manabi-todo-calendar`）。通知機能は後回し。
- **Superpowersの形式的な工程や実装済み機能の作り直しは不要**。Issueと現状コードの差分から、小さな変更→テスト→実ブラウザー確認で前進。

## 操作体験（確定した仕様）

### ホーム・カレンダー
- スマホの初期画面は「今日のダッシュボード」：今日の授業・直近の未提出課題・予定を簡潔に提示。
- PCのカレンダー初期表示は **B：Googleカレンダー型の週間時間軸**。**A：大学の5枠を中心とした時間割型**へ切替可能。月表示も維持。ユーザーが選んだ表示モードを端末ごとに記憶。
- カレンダーは通常時間割、学年暦、曜日振替、休講・補講、個別の授業回、課題、試験、個人・友人予定、学習タスクを統合表示。原データのコピー大量生成を避け、繰り返し規則＋例外を合成して描画する。
- 優先順位：本人が確定した変更 ＞ 個別授業例外 ＞ 学年暦の例外 ＞ 通常時間割。祝日だけで休講扱いにせず、不明な時刻や日付を勝手に補完しない。曜日振替は授業だけに作用し、個人予定や課題締切を動かさない。
- ホームウィジェットは表示ON/OFF・順番をカスタマイズ可能、端末ごとに記憶。「今日やること」は初期ONで、期限切れ・直近7日・優先表示タスクのみ提示。他は専用ToDoページで確認。

### 授業・ノート・PDF・付箋・タグ
- **カレンダー → 授業回（安定ID）→ ノート本文・PDF・付箋 → タグ横断検索 → 試験対策**を双方向につなげる。日付や授業回番号の変更で記録を削除・付け替えない。
- ノートは通常の自由記述文章。授業回には複数PDFを紐付け可能。付箋はPDFの特定ページ・座標に貼るものと、PDFに依存しない独立メモの両方。PDF上の付箋と付箋ボードは**同一ID・同一データ**。
- 付箋ボードの配置は **右側・下側・非表示** を切替でき、幅・位置などを端末ごとに保持。PDF＋ノートとの分割表示、資料への位置連携を維持。
- タグは授業間で共通。授業トップではその授業の `#テスト対策` / `#後で確認` / `#授業情報` 等の付箋を集約し、全体の付箋ページでは科目横断のタグ・本文・未完了検索を行う。先生の一言・普遍的な知識など、授業に属さない付箋も扱えるようにする。
- タグ（分類）とチェック済み（進捗）は別の状態。確認が完了しても付箋を失わず、タグで見返せる。

### ToDo・課題
- 付箋内のチェックリスト項目には独立した安定IDを付与。**項目ごとに全体ToDoへ載せるか利用者が選ぶ（C案）**。付箋内だけのチェック項目でToDoを埋めない。解除しても本文・チェック・期限は残す。
- ToDo一覧は登録済み付箋チェック項目、直接追加した個人ToDo、大学の正式な課題・学習タスクを統合してフィルタ可能。ToDoと付箋の完了状態は同一データを参照する。
- **期限付きの項目だけ**カレンダーへ表示（締切と作業予定は別概念）。日付のみなら「時刻未設定」と表示し、23:59などを推測しない。
- 大学の提出課題と本人の復習ToDoは異なる型として保存し、UI上では一緒に見せる。優先表示した期限なしToDoはホームの選択肢に入る。

### AIインポート
- ChatGPT/Geminiなど既存のチャットでPDF・画像を解析し、専用プロンプトをコピーして出力を1回貼り付ける**追加API料金0円の取り込み**。JSONは内部表現でよいが、ユーザーが手動編集する前提にしない。
- 「自分の時間割」「大学の開講科目カタログ」「学年暦」「授業資料・課題」で取り込み先を区別する。個人時間割を取り込むと授業一覧・曜日時限・初期ノートへ自動反映、時限不明は未配置へ。カタログは自動履修登録しない。
- 時間割の取り込み：**追加・更新**が初期、**全体置き換え**も可能。置き換えでは新規・安全な更新は自動で、**消える授業だけ人間が確認**し、ノートやタグを消さずアーカイブ。
- 同一授業・同一学年学期の重複回避、欠落・曖昧・矛盾・資料の一部読み落としを記録。取り込みバッチ単位の**差分履歴・取り消し**を目標にし、後から行った手動編集や端末同期を無差別に巻き戻さない。

- PR #8に付箋・チェック項目・選択的ToDo登録、授業回の日付、学年暦の基本サンプル、カレンダーの3表示形式、画面復帰・定期同期検査、ホームの一部表示設定がある。完全な製品要件を達成したわけではない。
- **Issue #11**：週間表示の重複予定が実ブラウザーで隠れた。重なり回避と操作・視認性の確認を優先。
- **Issue #10**：一時的な認証通信失敗を「未設定」と誤認し、再試行ができない。端末データ保護・有限タイムアウト・利用者向けのエラーと再試行を設計。
- **Issue #12**：依存関係の監査警告を調査し、互換性を維持した修正版に更新。無条件の `npm audit fix --force` を禁止。
- **Issue #9**：Previewの認証設定・同期DBはproductionから隔離して準備。秘密情報をIssueに掲載せず、本番データをPreviewへ接続しない。共有Preview URLだけではFirebaseが有効にならない。
- **Issue #13**：実PC・スマホの表示、2端末同期、競合・アカウント切替、実バックアップ・復元の受入確認。クラウド操作ツール由来のネイティブ日付ピッカーエラーをアプリの確定不具合として扱わない。

各担当はコード変更後に型・lint・テスト・ビルド・同期APIを実施し、実ブラウザー未検証は未検証と明示する。
